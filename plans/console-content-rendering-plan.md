# Console content rendering

Created 2026-10-21, for 42.0. Console only: no backend change, no migration, no new user-facing string.

Template, blog theme and web analytics content is written by workspace members or reported by a site's visitors, and shown to other members in the console. This change makes the console display it without running any script it carries, and makes the links and frames built from it point only where they should.

## Changes

1. **`console/src/utils/safeHtml.ts`** (new), four helpers:
   - `sanitizeHtml(html)`: DOMPurify with its default HTML profile, plus `target` and links to other apps (`webcal:`, `whatsapp:`…, while `javascript:`, `vbscript:` and `data:` stay refused), minus `<style>` and form controls. Keeps formatting, inline styles, classes, `data-*` and Liquid, `{{ url }}` in an `href` included. An editor saves what it loaded, so nothing an email may legitimately carry is dropped.
   - `parseHtmlInert(html)`: a new `<div>` of one `document.implementation.createHTMLDocument('')`, created on first use, for code that reads or rewrites markup. Nothing in that document is fetched or run.
   - `safeExternalUrl(url)`: an absolute http(s) URL on another origin than the console's, or `null`.
   - `isSafeHref(href)`: anything but a script or `data:` link, the rule `sanitizeHtml` applies to links in content, so a link shown on the canvas or in the side panel and one inside a block's HTML are judged alike. Liquid in a host (`https://{{ host }}/x`) passes.
   - `dompurify` becomes a direct dependency of the console. It was already installed, at the same version, as a dependency of `@ant-design/x-markdown`.
2. **Email editor canvas.** `MjTextBlock` and `MjButtonBlock` render `sanitizeHtml` of their content, memoised, and only while the block is not open in its editor. That content gets `contain: paint`, so what it draws, fixed positioning included, stays inside its block; content wider than its block is clipped there rather than drawn over its neighbours. A link click in a button's text selects the block, as it already did in a text block, instead of being followed. `MjImageBlock` and `MjSocialElementBlock` keep a link target on the canvas only if `isSafeHref` accepts it. The saved content is never rewritten.
3. **Block editors.** `TiptapRichEditor` and `TiptapInlineEditor` load their content through `sanitizeRichContent`, `getInitialInlineContent` and `prepareInlineContent`, which now apply `sanitizeHtml` themselves; the editors' text-only fallbacks apply it too. The initial content is computed once, when the editor is created, rather than on every render. The editing area gets `contain: paint` as the canvas does; the toolbar sits outside it and is not clipped.
4. **Markup helpers.** The tiptap `shared/utils.ts` helpers and `NotifuseEditor.addSyntaxHighlightingToHTML` parse with `parseHtmlInert`. Every node they create (span, text node, fragment) comes from that document, not from the page's.
5. **Previews.** The visual editor's email preview frame gets `sandbox="allow-popups allow-popups-to-escape-sandbox"`: no script, links still open in a new tab. The blog theme preview keeps `allow-scripts` and drops `allow-same-origin`. In that origin reading storage or cookies throws, so the preview document starts, right after its doctype, with a script giving the theme in-memory `localStorage`, `sessionStorage` (also readable and writable as properties, as a real Storage is) and `document.cookie`: `utils/previewStorage.ts` (new).
6. **Contact timeline, View website.** `webPageURL` appends a path that starts with `/` to the visit's origin, resolves any other value against it, and keeps the result only if it is on that origin and passes `safeExternalUrl`. When the workspace lists web analytics allowed domains, the visit's domain must be one of them, matched as the server matches incoming visits (case, spaces and a port ignored, IPv6 compared without brackets, `*.example.com` for the domain and its subdomains, never a bare TLD). The workspace website, a fallback its members set, is not held to the list. `WebPageDrawer` applies `safeExternalUrl` again before linking or framing.
7. **Editor side panel.** `StringPopoverInput` shows a value as a link only if `isSafeHref` accepts it, and `ImportFontInput` only if it is an absolute web address, which is all a stylesheet can be; anything else is plain text.
8. **e2e fixtures.** `auth.ts` and `public-pages.spec.ts` mock `**/config.js*`: `index.html` loads `/config.js?_t=…`, which the old pattern missed, so every spec landed on the setup page.
