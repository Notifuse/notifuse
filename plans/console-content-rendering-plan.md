# Console content rendering

Created 2026-10-21, for 42.0. Console only: no backend change, no migration, no new user-facing string.

Template, blog theme and web analytics content is written by workspace members or reported by a site's visitors, and shown to other members in the console. This change makes the console display it without running any script it carries, and makes the links and frames built from it point only where they should.

## Changes

1. **`console/src/utils/safeHtml.ts`** (new), helpers:
   - `sanitizeHtml(html)`: a DOMPurify instance of its own (the configuration reaches nothing else on the page) with its default HTML profile, plus `target` and links to other apps (`webcal:`, `whatsapp:`…, while `javascript:`, `vbscript:` and `data:` stay refused), minus `<style>`, form controls, image maps (an area is a link the canvas would follow), audio and video (they would play in the console) and the builder's own `data-block-id` (it locates blocks on the canvas). Keeps formatting, inline styles, classes, `data-*` and Liquid, `{{ url }}` in an `href` included.
   - `sanitizeEditorHtml(html)`: the same, through a second instance, for the content a block editor loads. It also keeps attribute values that `sanitizeHtml` drops for containing `-->` or `]>` (a link to `https://example.com/?q=a]>b`), since an editor saves what it loaded and nothing an email may legitimately carry should be lost on the next edit. Those values are dropped because markup carrying them can parse differently once inserted elsewhere; an editor parses what it loads in a document that runs nothing and builds its own DOM from the result. As DOMPurify requires for keeping them, this instance takes HTML only: SVG and MathML, which the editors have no place for, are left out with what they contain.
   - `containedContentStyle`: paint containment for the element that shows content, on the canvas or in an editor, with a 25px `overflow-clip-margin`, the padding an email gives its text by default. The element is a stacking context, so whatever the content's `z-index`, the toolbars stacked above the block (the formatting toolbar, the block's action buttons) stay above what it draws.
   - `parseHtmlInert(html)`: a new `<div>` of one `document.implementation.createHTMLDocument('')`, created on first use, for code that reads or rewrites markup. Nothing in that document is fetched or run.
   - `safeExternalUrl(url)`: an absolute http(s) URL on another origin than the console's, or `null`.
   - `textOnlyHtml(html)`: the text of some HTML, escaped so it shows as text, for the editors' text-only fallbacks, so escaped text in content never comes back as markup.
   - `isOpenableUrl(url)`: an absolute web, mail or phone address, the links the side panel offers to follow; any other scheme would hand the click to an app.
   - `isSafeHref(href)`: anything but a script or `data:` link, the verdict the same instance gives a link in content (`isValidAttribute`), so an image or social link on the canvas and one inside a block's HTML are judged alike. Liquid in a host (`https://{{ host }}/x`) passes.
   - `dompurify` becomes a direct dependency of the console. It was already installed, at the same version, as a dependency of `@ant-design/x-markdown`.
2. **Email editor canvas.** `MjTextBlock` and `MjButtonBlock` render `sanitizeHtml` of their content, memoised, and only while the block is not open in its editor. That content gets `containedContentStyle`, so what it draws, fixed positioning included, stays on its block; what it draws just past its box, a shadow, an italic overhang or a list marker, still shows up to 25px out, into the block's padding, as in the email, where the browser supports `overflow-clip-margin`. That containment sits on a box of its own, sized by the content, so a block given a fixed height or width cuts off no text the email would show; for the button, an inline-block that carries the button's text decoration, which would not reach into it otherwise. A click on the content of either block only selects it: nothing in the content (a link, a label naming a console field) acts on it, and a middle click on any canvas link, image and social links included, opens nothing. `MjImageBlock` and `MjSocialElementBlock` keep a link target on the canvas only if `isSafeHref` accepts it. The saved content is never rewritten.
3. **Block editors.** `TiptapRichEditor` and `TiptapInlineEditor` load their content through `sanitizeRichContent`, `getInitialInlineContent` and `prepareInlineContent`, which now apply `sanitizeEditorHtml` themselves; the text-only fallbacks, here and in `getInitialInlineContent`, keep the text as text (`textOnlyHtml`). The initial content is computed once, when the editor is created, rather than on every render. The editing area gets `containedContentStyle` as the canvas does; the toolbar sits outside it and is not clipped. `injectTiptapStyles` looks for its style in the head, since content on the page may carry any id.
4. **Markup helpers.** The tiptap `shared/utils.ts` helpers and `NotifuseEditor.addSyntaxHighlightingToHTML` parse with `parseHtmlInert`. Every node they create (span, text node, fragment) comes from that document, not from the page's.
5. **Previews.** The visual editor's email preview frame gets `sandbox="allow-popups allow-popups-to-escape-sandbox"`: no script, links still open in a new tab. The blog theme preview keeps `allow-scripts` and drops `allow-same-origin`. In that origin reading storage or cookies throws, so the preview document starts, right after its doctype, with a script giving the theme in-memory `localStorage`, `sessionStorage` (also readable and writable as properties, as a real Storage is) and `document.cookie` (a cookie set to expire is removed): `utils/previewStorage.ts` (new). IndexedDB and the Cache API stay unavailable in the preview.
6. **Contact timeline, View website.** `webPageURL` appends a path that starts with `/` to the visit's origin, resolves any other value against it, and keeps the result only if it is on that origin and passes `safeExternalUrl`. When the workspace lists web analytics allowed domains, the visit's domain must be one of them, matched as the server matches incoming visits (case, spaces and a port ignored, IPv6 compared without brackets, which the recorded domain lacks and the URL gets back, `*.example.com` for the domain and its subdomains, never a bare TLD). When it lists none, the domain must be the host of the workspace website, `www.` or not: nothing else vouches for what the visitor reported, which could name a machine on the member's own network. A domain taken off the list takes the previews of its earlier visits with it. The workspace website, a fallback its members set for rows recorded without a domain, is held to neither rule. `WebPageDrawer` applies `safeExternalUrl` again before linking or framing.
7. **Editor side panel.** Both use one Liquid check (`utils/liquid.ts`, new, outputs and tags). `StringPopoverInput` shows a value as a link only if it holds no Liquid and `isOpenableUrl` accepts it, and `ImportFontInput` only if it holds no Liquid and `safeExternalUrl` accepts it, a web address being all a stylesheet can be; anything else is plain text.
8. **e2e fixtures.** `auth.ts` and `public-pages.spec.ts` mock `**/config.js*`: `index.html` loads `/config.js?_t=…`, which the old pattern missed, so every spec landed on the setup page.
